## What it is
Browser-based book writing app. One main folder = library; each subfolder = a book; each `NN-title.md` inside = a chapter (`# Title` first line, body after). Reads/writes via File System Access API (Chrome/Edge, standalone file); falls back to folder upload + `.md` download where unavailable (incl. inside the preview — "Could not open" there is expected).

## UI (two screens + overlays)
- **Books**: grid of book covers (2:3; spine strip on left, two offset page edges behind right/bottom; #525252 border → #000 on hover and the cover lifts `translate(-3px,-3px)` off its page stack, .25s ease-out; title on cover in the content font; meta beneath; click = open, double-click = rename inline). Top row: folder name on the left (20px/600, Inter — 2026-10-07), `+` icon (new book) and gear icon (Settings) on the right. **New book** = the **Book modal** opens empty (`renameIdx: -2`, 2026-10-07 — the old inline rename row below the grid is gone); nothing is created in memory or on disk until a non-empty unique name is saved — Esc/Cancel/click-outside/empty discards. **Rename** (double-click a cover, or the rail gear in Book view) = the same modal: name input (placeholder `Book name`), `Words` row (number = word goal) and `Color` row (9 swatches = cover spine colour), Cancel/Save, then hairline + full-width `Delete book` (existing books only) → modal "Delete “Book”?" Cancel/Delete (z-index 21, above the Book modal); delete removes the folder recursively from disk and the book from the library. Words/Color live in **`book.json`** inside the book folder (written only when set, deleted when cleared — like notes; unknown keys preserved for later fields; in the zip). Cover meta shows `W / G words` and the Book-view word count `cw · bw / G` when a goal is set. The same modal serves chapter and book deletes (`confirmBook` flag). Status line at bottom. **Empty library** (2026-10-07): when the folder holds no book folders the grid area shows one centred black `New book` button (opens the new-book row; hidden while that row is open). A folder with loose `.md`/`.txt` files in its root is refused with an alert card — `This folder should only contain subfolders.` + `OK` (same card style as Delete; works over the gate; picker, resume, sync, upload fallback); the remembered handle is kept so Resume retries after the file is moved.
- **Folder gate**: the app is a folder utility — until a folder is open (`folderOpen` state, set only by `loadLibrary`; books are NOT cached — the folder is the only source of truth, localStorage holds settings only) the only thing rendered is a centred screen: heading "Start Writing" + primary button + status. No folder name is shown. No shelf, no settings, no shortcuts, no overlays. **Remembered folder (2026-10-07)**: the `FileSystemDirectoryHandle` is stored in IndexedDB (`writer`/`kv`/`lib`) after the picker; `boot()` on mount reads it and calls `queryPermission` — `granted` loads straight from disk (no gate), `prompt` shows the gate with `Resume` (→ `requestPermission`; Chrome 122+ offers "Allow on every visit" on this prompt, never on the picker's own prompt) plus a secondary `Open folder` text button; a missing folder is forgotten (`Folder not found`). `booting` is true until that check finishes and nothing renders meanwhile. **Log out** is the only thing that forgets the handle.
- **Markdown** in the body: files stay raw markdown. Editor is iA-Writer style — each `<p>` is decorated in place (`decorate(p)`): line types `#`/`##`/`###`, `>`, `-`/`*`/`+`, `1.`, `---` get inline styles on the `<p>`; inline `**bold**`, `*italic*`/`_italic_`, `~~strike~~`, `` `code` `` wrap in `<strong>/<em>/<s>/<code>`; markers stay in the text, dimmed #a3a3a3 (so `serialize` → innerText round-trips exactly). Paragraph innerHTML is rewritten only when its structure changes (caret restored by text offset) — native undo is lost at that point only. Print renders real markdown (`mdHtml`: h1–h3, blockquote, ul/ol, hr, inline). Markdown download stays raw. Word count ignores markers.
- **Find**: magnifier in the chapter tools (or ⌘F) opens an inline field; CSS Custom Highlight API (`::highlight(wr-find)` grey, `::highlight(wr-cur)` black) — no DOM changes; Enter/Shift+Enter or chevrons step and scroll the match to centre; Esc closes. Tools strip stays visible while find is open.
- **Book**: left sidebar (280px) top: icon row `←` (back to Books) … `+` (new chapter — creates an untitled chapter immediately and focuses the title; the user explicitly declined a "pending until named" flow for chapters) · print (book scope) · download (whole book as `Book.zip` — folder `Book/NN-title.md`, store-only zip built by hand in `zip()`, no library) · gear (**Book** modal on the current book, 2026-10-07); book name (read-only, wraps — never truncated) on its own line beneath. No text buttons in the rail. Then chapter list (drag to reorder, word counts); bottom row: `Settings` (gear + label, left, 2026-10-07) · status line (right-aligned) · collapse chevron (always visible, #a3a3a3). **Collapsed rail** (56px, `railCollapsed`, persisted in localStorage `writer.rail` = `min`/`max`): chapter numbers only (title as tooltip, current highlighted, still draggable), `+` beneath, gear box (Settings) then expand chevron at the bottom; no title/status/other icons. Chapter-tools strip `left` follows rail width. When collapsed, the book title appears as a small uppercase grey caption (11px, #a3a3a3) above the chapter title in the main column. Main top-right icons (invisible until the mouse moves over that strip, fade out .4s after leaving): find, fullscreen (Write), print (chapter scope), download (chapter as "Book — Chapter.md"), notes (toggle pane; icon is #000 when open or when the chapter has notes), trash (delete chapter → modal "Delete “Title”?" Cancel/Delete) — in that order. Then editable chapter title, text.
- **Notes** (per chapter): sidecar file `NN-title.notes.md` next to the chapter file (same slug; only written when non-empty, deleted when emptied; paired on load by slug, case-insensitive; included in the book zip; part of `bookKey`). Not printed, not word-counted. UI: right pane (300px, `notesOpen`, persisted in localStorage `writer.notes` = `open`/`closed`), padding 24px top to align with the rail; header row = collapse chevron `›` (#a3a3a3, always visible) then uppercase `NOTES` caption; plain textarea in the content font (14px/1.7); tools strip and word count shift left of it. Hidden in Write mode.
- **Write** = fullscreen: typewriter scroll (top pad 45vh so the first line can sit at centre; caret scrolled to centre on entry via rAF), with Typewriter off the pad is 96px and it opens at the top; dim non-current paragraphs, word count bottom-right, `×` icon top-right (or Esc) to exit. **Typewriter / Dim are toggled here** (2026-10-07): two quiet text buttons bottom-left (`#000` on, `#a3a3a3` off) — the aids only act in Write, so their switches live in Write, not in Settings; still persisted in `writer.json`.
- **Print** overlay: scoped by which print icon opened it — "Print Chapter"/"Print Book" + two cards (Receipt | Letter). Markdown download is NOT in this overlay (user hated it) — it has its own download icons. PDF save-as title follows the same naming. Printing builds a clean hidden iframe document (no app CSS bleed). Each chapter breaks to a new page, `break-inside:avoid` (never split a chapter). Receipt: NO `@page size` (Chrome ignores it for physical printers, centres/shrinks text — user was furious about this several times; DO NOT add it back, DO NOT touch margins) — `@page{margin:2mm 3mm}` only, text fills the roll size chosen in the print dialog, 1.5in `.tail` spacer block after each chapter (ends with a tiny `·` so Chrome keeps the blank space). Font size = Size setting × 0.5 (receipt) / × 0.67 (letter). Cut-per-page lives in the Epson TM-T88VI driver, not the app. Letter: 25mm margins. **Receipt width** (58mm · 80mm) is chosen in this overlay under the Receipt card at print time — `printRoll` component state, default 80, deliberately NOT stored (user, 2026-10-07: receipt settings are a print-time choice, not a setting). **Page numbers** toggle (checkbox under the Letter card, `settings.pageNums`, persisted; Letter only): uses CSS `@page` margin boxes — `@top-center{content:"Book title"}` and `@bottom-center{content:counter(page)}`, 9pt, inside the 25mm margins (Chrome 131+). NO fixed page boxes, NO `@page size`, NO manual pagination (a hand paginator was tried and Chrome shrank the page — user said "horrible"; never again). Receipt is untouched by this. Print markdown is flat: lists → `<p class="li">• …`, quotes → `<p class="q">`. The roll width is read in `doPrint` (`w`) but still unused by the receipt CSS — width comes from the printer's paper size (see the no-`@page size` rule above). During print the parent `document.title` is swapped to the doc title and restored on afterprint (only visible in the standalone file, not the embedded preview).
- **Settings** overlay: Folder (Choose/Change), Sync (flush pending, then disk is truth), Font (sans/serif/mono/courier), Size (Typewriter/Dim → Write screen, Receipt width → Print overlay, 2026-10-07); **Log out** as a full-width bottom row under a hairline (2026-10-07) — flushes saves, forgets the folder handle, drops all books from memory, returns to the gate.

## Behaviour rules learned from the user (do not regress)
- Minimal, bare verb buttons, no descriptive UI text, no browser `confirm()`/`alert()`.
- No multiple layout "directions". Rail icons (gear, book print) and chapter-area icons are hover-revealed per user request (state-driven opacity, fade transition).
- Book name is NOT editable inline in the chapter area — rename via the rail gear's Book overlay or on the Books screen.
- Settings belongs top-right, not at the bottom. Infrequent actions (Rename) must not take real estate.
- Never allow creating a book without a folder. Opening a folder replaces the library with exactly what is on disk — no cached orphans (user explicitly rejected them). Remember the folder handle, never its contents.
- Every line is its own line in the file — blank lines round-trip exactly (editor `<p>` per line, `margin:0`). Paste: multi-line plain text is inserted as one `<p>` per line (empty line → `<p><br></p>`); `serialize` trims trailing newlines per `<p>` so no extra blank lines appear.
- Font setting applies ONLY to content (cover titles, chapter title, body, print) — never to UI chrome (nav, sidebar list, buttons, settings stay Inter).
- Destructive actions use an in-app modal (Cancel / Delete), never a two-step "Confirm" button.
- Autosave: every change (text, title, notes, chapter add/delete/reorder) marks the book dirty and writes to disk ~0.8s later; book create/rename/delete write immediately; flushed on tab hide/pagehide, and `beforeunload` flushes + prompts if dirty. ⌘S forces. Status shows "Saved h:mm". **Settings persist in `writer.json` in the library root** (2026-10-07; read on open, written on change; localStorage `writer.lib.v3` is only the fallback copy). **Folder watcher** (2026-10-07): visible tab polls every 3 s comparing per-book file stamps (name+lastModified+size, no reads) + `writer.json`; changed clean books are re-read in place (position kept by chapter index; a replaced open chapter puts the caret at the end unless focus is in notes/find), dirty or just-typed-in books wait, added/removed folders follow, settings file changes apply; own writes update the stamps. **Sync** = flush, then re-read everything from disk (never pushes app copies over outside edits any more). **Writes self-heal permission** (2026-10-07): Chrome drops a one-time grant after backgrounding, so every write path calls `ensureWrite()` (query → request); a failed autosave keeps the book dirty and the next click/keypress re-requests and flushes.

Printing is never themed — paper stays white — and book spine pastels are the same in both themes.

## 2026-10-08 — spoken punctuation
- User: saying `period`, `comma`, `exclamation point` while dictating added nothing (new paragraphs worked). Cause: only `new paragraph` / `new line` were command words; Chrome's desktop engine and Speech.framework both leave the rest as literal words (Apple's `addsPunctuation` is automatic only). Now `Dictation.spoken` maps the macOS Dictation command vocabulary to marks before a segment is joined — attached to the word before, capital after a sentence end, no doubling of a mark the recognizer or the paragraph already has — and the partial preview shows the marks too. Same pass in Sermon Builder (`spokenPunctuation` in `app/src/lib/dictation.js`, unit-tested there).
